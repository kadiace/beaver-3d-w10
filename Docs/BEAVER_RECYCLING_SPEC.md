# 비버 분리수거 POC — 상세 기획 명세

- 문서 버전: 0.4
- 작성일: 2026-11-11
- 기준 프로젝트: `beaver-3d-w10`, `develop/beaver-recycle`
- 상태: 핵심 플레이 루프의 코드와 씬 구성을 복원했다. Unity 런타임 소스 컴파일은 통과했으며, Editor 임포트와 Play Mode 검증은 남아 있다.
- 사용자 제시 콘셉트인 분리수거·묶음 제출·목재 재화를 중심으로, 미정인 조작과 수치는 아래 POC 초기안으로 제안한다.
- 기존 빌드의 경과와 결합 점수 설명은 `CREEK_SYNERGY.md`, 이전 배치형 게임은 `RESTORE_CASTLE_3D.md`에서 확인한다. 새 분리수거 버전을 제작할 때는 이 문서를 규칙 기준으로 사용한다.

## 1. 게임 개요

### 1.1. 콘셉트

쓰레기가 계속 밀려오는 강에서 비버가 분리수거 직원으로 일한다. 플레이어는 비버를 움직여 쓰레기를 집고, 같은 종류를 접착해 한 묶음으로 만들고, 강 옆의 투입구에 제출한다.

쓰레기를 올바르게 분류하면 점수를 얻는다. 같은 종류를 한꺼번에 많이 제출하면 추가 점수를 얻지만, 묶음이 커질수록 운반이 느려지고 다른 종류가 섞일 위험도 커진다. 쓰레기를 잘못된 투입구에 넣거나 폭포로 흘려보내면 감점된다.

나뭇가지와 통나무는 분리수거 점수와 별도로 관리하는 목재 자원이다. 나무가 폭포 경계를 넘으면 목재를 획득하고, 퇴근 후 능력을 올리는 데 사용한다. 목재는 식량과 건축 재료라는 설정을 함께 담는 하나의 재화로 표현한다.

### 1.2. POC에서 확인할 재미

1. 흘러가는 기물을 따라 움직이며 집기·붙이기·제출을 수행하는 조작감.
2. 가까운 작은 묶음을 먼저 제출할지, 더 큰 묶음을 만들지 결정하는 재미.
3. 종류가 섞인 묶음의 감점과 다시 분리하는 수고 사이의 판단.
4. 점수를 위한 쓰레기 처리와 다음 날 성장을 위한 목재 회수 사이의 시간 배분.

### 1.3. 제작 범위

- 3D 강 하나와 비버 한 마리를 사용한다. 씬에서 각도를 조절하는 비스듬한 정사영 탑뷰와 물리 기물 표현을 사용한다. 초기 카메라는 Euler 기준 회전 `(0, 0, 0)`에서 X축 pitch만 55도로 올려 하류에서 상류와 폭포를 바라본다.
- 플라스틱·유리·비닐·금속의 4개 분리수거 종류, 나뭇가지·통나무를 제공한다.
- 5일 캠페인, 하루 목표 점수, 퇴근 후 업그레이드, 성공·실패 및 재시도를 구현 대상으로 둔다.
- 희귀도별 복잡한 능력, 재질 조합별 특수 점수, 오크통 폭발, 식물 성장, 덩쿨 번식은 새 버전의 등장 풀에 포함하지 않는다.
- 비버의 허기·체력·전투, 댐 건축 시뮬레이션, 영구 성장과 저장, 무한 모드는 후속 범위로 둔다.

## 2. 공간과 화면 구성

| 구역 | 역할 |
|---|---|
| 상류 공급 구역 | 일정 간격으로 기물이 생성되어 강으로 들어온다. 플레이어는 공급 위치를 바꾸지 않는다. |
| 하천 작업 구역 | 비버가 움직이고 기물을 집거나 결합하는 얕은 물 구역이다. 기물은 하류 방향으로 흐른다. |
| 강 옆 투입구 | 재질별 투입구 4개를 배치한다. 비버가 접근해 들고 있는 묶음을 제출한다. |
| 하류 폭포 | 놓친 쓰레기의 감점과 목재 회수를 정산하는 경계다. 화면에 보이는 폭포와 실제 판정선을 일치시킨다. |
| 퇴근 화면 | 하루 결과를 확인하고 목재를 써서 다음 날을 준비한다. 월드 진행은 정지한다. |

- 투입구는 양쪽 강가에 두 개씩 배치하는 것을 초기 레이아웃으로 사용한다. 모든 투입구에 비버가 걸어서 접근할 수 있다.
- 투입구 간격은 한 번에 두 투입구가 제출 대상으로 선택되지 않도록 확보한다.
- 투입구에는 이름, 고유 아이콘, 대표 기물 그림을 표시한다. 색상 외에도 재질을 구분할 수 있어야 한다.
- 아직 등장하지 않는 종류의 투입구는 덮개와 비활성 표시를 사용한다.
- 비버는 하천 작업 구역과 투입구 앞 통로를 이동한다. POC에서는 일정한 높이를 유지하며, 강물에 떠밀리거나 폭포로 추락하지 않는다.
- 비버와 쓰레기의 충돌이 이동을 완전히 막지 않게 한다. 운반 중인 기물의 모양과 결합 상태는 물리적으로 표현한다.

## 3. 비버 조작

### 3.1. 기본 입력

| 조작 | 액션 | 동작 |
|---|---|---|
| WASD / 방향키 | `Recycling/Move` | 비버를 XZ 평면에서 이동한다. 대각선 이동 속도는 동일하게 정규화한다. |
| 좌클릭 | `Recycling/PrimaryClick` | 들고 있지 않으면 커서가 가리키는 가까운 기물을 집는다. 운반 중이면 묶음을 내려놓는다. |
| E | `Recycling/Submit` | 활성 투입구 앞에서 들고 있는 묶음을 제출한다. |
| Q | `Recycling/SplitBundle` | 운반 중인 묶음의 모든 결합을 풀고 기물을 내려놓는다. |
| 짧은 우클릭 | `Recycling/SecondaryClick` | 기물 정보를 고정하고 해당 기물을 카메라로 추적한다. 빈 공간에서는 추적을 해제한다. |
| 휠 | `Recycling/CameraZoom` | 카메라를 확대·축소한다. |
| Esc | `Recycling/Cancel`, `UI/Cancel` | 열려 있는 설명·메뉴를 닫거나 일시정지 메뉴를 연다. |

- 모든 바인딩은 공용 Input Actions 에셋에 저장하고 `Managers.Input`을 통해 읽는다. 새 `Recycling` 맵이 이동·집기·카메라·제출·묶음 분리를 제공하며, 기존 `Player`와 `UI` 맵은 유지한다. 런타임에 액션 바인딩을 덧씌우지 않는다.
- 새 분리수거 씬은 `Recycling` 맵을 사용한다. 기존 `Player`·`UI` 액션 맵과 회전·홍수 미리보기 조작은 호환을 위해 보존한다.
- 비버를 이동하기 시작하면 기물 추적을 해제하고 카메라가 비버를 부드럽게 따라간다.
- 클릭 대상이 집기 범위 밖이면 집기 입력은 실행되지 않으며, 대상과 거리 제한을 짧게 표시한다.

### 3.2. 초기 능력치

| 항목 | 초기값 |
|---|---:|
| 기본 이동 속도 | 초당 4.5 월드 단위 |
| 집기 거리 | 비버와 대상 표면 사이 1.8 월드 단위 |
| 운반 한도 | 기물 6개 |
| 제출 상호작용 거리 | 투입구 앞 지점에서 1.8 월드 단위 |
| 운반 이동 배율 | `max(0.6, 1 - 0.05 × max(0, 운반 개수 - 3))` |

모든 기물은 크기와 관계없이 운반 칸 하나를 사용한다. 초기에는 3개까지 기본 속도를 유지하고, 6개를 들면 이동 속도가 85%가 된다. 기물의 질량을 별도의 운반 제한 수치로 추가하지 않는다.

## 4. 집기·접착·내려놓기

### 4.1. 집기

- 커서 아래에 있는 기물 하나를 대상으로 집기 거리를 검사한다.
- 대상이 다른 기물과 결합되어 있으면 연결된 묶음 전체를 집는다. 정산 중인 기물은 집을 수 없다.
- 묶음 전체가 운반 한도를 초과하면 집기를 실행하지 않고 필요한 칸 수를 표시한다.
- 집은 묶음은 비버 앞의 운반 지점을 따라 움직인다. 커서를 멀리 옮겨도 기물이 순간 이동하지 않는다.
- 한번 내려놓은 기물이나 묶음도 다시 집을 수 있다.

### 4.2. 접착

- 접착은 비버가 들고 있는 묶음과 다른 기물이 접촉할 때 발생한다. 물에 떠 있는 기물끼리의 일반 충돌에서는 새 결합을 만들지 않는다.
- 접촉한 상대가 묶음이면 그 묶음 전체를 합친다. 기존 결합망이 같은 대상에는 중복 결합을 만들지 않는다.
- 합친 결과가 운반 한도를 넘으면 상대 묶음 전체를 받지 않는다. 임의의 일부만 떼어 붙이지 않는다.
- 재질에 관계없이 결합할 수 있다. 다른 종류가 섞이는 실수도 허용하며 색상·아이콘과 제출 예상 점수로 알려준다.
- 조인트는 현재 빌드의 고정 결합을 활용한다. POC에서는 일반 충격으로 임의 파단되지 않게 하여 분류와 운반에 집중한다.
- 내려놓아도 기존 결합은 유지된다. 묶음의 특정 기물 하나가 물에 닿으면 연결된 기물들이 함께 물살을 받는다.

### 4.3. 묶음 풀기

- Q를 누르면 운반 중인 묶음 전체의 결합을 해제하고 모든 기물을 현재 위치에 내려놓는다.
- 분리 직후 0.5초 동안 새 결합을 막아 같은 자리에서 즉시 다시 붙는 현상을 방지한다.
- 분리에는 점수·목재 비용을 부과하지 않는다. 이동과 다시 모으는 시간이 비용이 된다.
- 실수로 다른 종류를 섞었을 때 분리하거나, 감점을 감수하고 제출하는 선택을 제공한다.

## 5. 기물과 분류

### 5.1. 분류 체계

| 종류 | 예시 기물 | 올바른 처리 | 초기 수치 |
|---|---|---|---:|
| 플라스틱 | 플라스틱 병, 플라스틱 용기 | 플라스틱 투입구 | 개당 3점 |
| 유리 | 유리병, 유리 단지 | 유리 투입구 | 개당 3점 |
| 비닐 | 비닐봉투, 포장 비닐 | 비닐 투입구 | 개당 3점 |
| 금속 | 찌그러진 캔, 금속 통 | 금속 투입구 | 개당 3점 |
| 목재 | 나뭇가지, 통나무 | 폭포 통과 시 자동 획득 | 나뭇가지 1목재, 통나무 3목재 |

- 모든 기물은 분류 하나만 가진다. 복합 재질과 오염 여부에 따른 별도 세척 규칙은 POC에 넣지 않는다.
- 쓰레기 재질은 획득 점수보다 운반 형태와 분류를 위한 구분이다. 재질별 기본 점수는 동일하게 둔다.
- 플라스틱 병과 유리병처럼 실루엣이 비슷한 기물은 라벨·투명도·재질 아이콘으로 구분한다.
- 기존 `empty_bottle`, `dented_can`, `bucket`, `waste_bag_small`, `branch`, `log` 프리팹은 외형 제작의 기반으로 활용할 수 있다. 새 분류와 능력은 별도 기물 정의에 명시한다.
- 새 게임의 등장 목록은 분리수거 전용 풀로 관리한다. 기존 카탈로그 전체에서 시작 전용 기물만 빼는 방식으로 구성하지 않는다.

### 5.2. 기존 특수능력의 처리

기존 재질 조합 점수, 기본 내구도, 희귀도, 쓰레기 봉투의 묶음 점수 배율 감소, 냄새 덩어리의 감점 능력을 새 점수 계산에 합산하지 않는다. 새 버전의 점수 근거는 투입구 일치 여부와 올바른 묶음의 크기로 통일한다.

해바라기·덩쿨·석재·보석·오크통 등 새 테마의 분류에 포함하지 않은 기물은 새 등장 풀에서 제외한다. 기존의 비닐봉투 외형을 활용하더라도 새 비닐 기물은 일반 분리수거 대상으로 취급한다.

## 6. 투입구와 제출

- 비버가 활성 투입구의 상호작용 범위에 들어가면 대상 투입구를 강조하고 ‘E 제출’을 표시한다.
- 기물을 들고 있을 때 제출 예상 점수와 포함된 재질 개수를 보여준다.
- E를 누르면 들고 있는 연결 묶음 전체를 한 번에 제출한다. 기물들이 투입구의 작은 콜라이더 안에 모두 들어갈 필요는 없다.
- 입력 순간의 구성원과 분류를 확정하고, 전체를 정산 중 상태로 바꾼 뒤 점수를 적용한다.
- 제출된 기물은 운반·접착·폭포 판정에서 제외하고 투입구로 흡수되는 연출 후 풀에 반환한다.
- 잘못된 재질도 제출할 수 있다. 예상 감점을 표시한 상태에서 입력하면 실제 감점과 제거를 실행한다.
- 비활성 투입구, 범위 밖, 빈손 상태에서는 제출을 실행하지 않는다.

## 7. 점수 규칙

### 7.1. 기본 정산

| 상황 | 결과 |
|---|---:|
| 쓰레기를 맞는 투입구에 제출 | 개당 +3점 |
| 쓰레기를 다른 종류의 투입구에 제출 | 개당 -4점 |
| 목재를 분리수거 투입구에 제출 | 0점, 목재 획득 없음. 함께 제출한 쓰레기는 정상 정산 |
| 쓰레기가 폭포 또는 하천 이탈 경계를 통과 | 개당 -2점 |
| 올바른 종류만 묶어서 제출 | 기본 점수에 묶음 보너스 적용 |

- 점수는 음수가 될 수 있다.
- 묶음 안의 각 기물은 한 번만 정산한다. 제출과 폭포 판정에 동시에 점수나 재화를 지급하지 않는다.
- 하루 목표는 그날의 순점수로 판정한다. 전날의 초과 점수를 다음 날 목표 달성에 사용하지 않는다. 누적 점수는 결과 화면용으로 함께 기록한다.
- 기존 오염도 100에 의한 별도 게임 오버는 새 POC에서 사용하지 않는다. 놓친 쓰레기의 비용은 점수 감점으로 표현한다.

### 7.2. 올바른 묶음 보너스

보너스는 제출된 묶음의 모든 기물이 해당 투입구의 재질일 때 적용한다.

| 묶음 개수 | 추가 배율 | 제출 점수 예시 |
|---:|---:|---:|
| 1개 | 0% | 3점 |
| 2~3개 | +25% | 2개 7점, 3개 11점 |
| 4~5개 | +50% | 4개 18점, 5개 22점 |
| 6개 이상 | +75% | 6개 31점, 8개 42점 |

`정상 묶음 점수 = floor(개수 × 3 × (1 + 추가 배율))`

묶음의 점수 합계에서 한 번만 소수점을 버린다. 업그레이드로 8개 이상을 운반해도 추가 배율은 75%에서 유지한다.

### 7.3. 다른 종류가 섞인 묶음

한 개라도 다른 종류나 목재가 들어 있으면 묶음 보너스는 없다. 투입구와 일치하는 쓰레기는 개당 +3점, 다른 종류의 쓰레기는 개당 -4점으로 합산한다. 목재는 점수와 감점에 포함하지 않으며, 투입구에 제출하면 목재 보상 없이 제거한다.

- 플라스틱 4개를 플라스틱 투입구에 제출: `4 × 3 × 1.5 = 18점`.
- 플라스틱 4개와 유리 1개를 플라스틱 투입구에 제출: `4 × 3 - 4 = 8점`.
- 플라스틱 4개와 나뭇가지 1개를 플라스틱 투입구에 제출: `4 × 3 = 12점`, 목재 보상 없음.
- 플라스틱 4개를 유리 투입구에 제출: `4 × -4 = -16점`.

재질이 맞는 기물끼리 묶을 이유가 명확해지고, 혼합 묶음을 대량으로 밀어 넣어 보너스를 얻는 방법은 생기지 않게 한다.

## 8. 폭포와 목재 재화

### 8.1. 폭포 정산 단위

- 폭포는 기물별로 판정한다. 연결된 기물 하나가 경계를 넘었다고 나머지 묶음을 즉시 전부 정산하지 않는다.
- 경계를 넘은 기물은 점수 또는 목재를 정산하고, 해당 기물의 결합을 해제한 뒤 제거한다. 남은 묶음은 계속 움직인다.
- 현재 루트 Z 좌표 판정 구조를 활용하되, 경계 위치는 씬 설정으로 분리하여 폭포의 실제 위치에 맞춘다.
- 폭포 밖의 Y 하한 등 이탈 보조 판정에서도 쓰레기는 동일하게 감점한다. 다른 방향으로 버려 감점을 피할 수 없게 한다.

### 8.2. 목재 획득

- 목재는 첫날 0에서 시작하고 성공한 날 사이에 이월한다.
- 폭포를 통과한 나무는 플레이어가 건드렸는지와 관계없이 나뭇가지 1, 통나무 3목재를 지급한다.
- 보상 판정은 나무 기물마다 독립적으로 하며, 연결 묶음의 나머지 기물은 각자의 폭포 판정을 유지한다.
- 목재는 분리수거 점수와 묶음 배율에 포함되지 않는다. 투입구에 쓰레기와 함께 제출해도 목재는 감점 없이 제거되지만, 목재 보상은 지급하지 않으며 순수 재질 묶음 보너스도 받지 않는다.
- 목재 아이콘은 나무 종류를 표시한다. 회수 여부를 나타내거나 보상 자격을 제한하지 않는다.
- 목재가 폭포가 아닌 이탈 구역으로 사라지거나 하루 종료까지 남으면 목재를 지급하지 않는다.

## 9. 하루의 진행과 목표

### 9.1. 진행 순서

`출근 준비 → 60초 공급 작업 → 30초 마감 정리 → 하루 정산 → 업그레이드 → 다음 날`

1. 출근 준비에서 오늘의 목표, 등장 재질과 투입구를 확인하고 ‘출근’ 버튼을 누른다.
2. 즉시 타이머와 기물 공급을 시작한다. 첫 기물이 폭포에 닿기를 기다려 시간을 시작하지 않는다.
3. 60초가 지나면 새 기물 생성을 멈추고 ‘마감 정리 30초’로 전환한다. 기존 기물의 흐름과 비버의 모든 작업은 계속된다.
4. 마감 정리 중 강 위의 기물이 모두 사라지면 즉시 하루를 정산한다. 90초가 끝나도 남아 있는 경우 입력과 물리 진행을 멈추고, 남은 쓰레기에 개당 -2점을 적용해 제거한다. 들고 있는 쓰레기도 포함하며, 남은 목재는 획득 없이 제거한다.
5. 마감 처리를 포함한 오늘의 순점수가 목표 이상이면 클리어한다. 이미 목표를 넘겼어도 마감 전까지 작업을 계속한다.
6. 성공한 날의 목재를 다음 날로 넘기고 업그레이드 화면을 연다. 5일차 성공 시 최종 클리어 화면을 표시한다.

마감 시간은 새 기물의 낙하와 상류에서 폭포까지의 기본 이동 시간을 포함할 수 있어야 한다. 아래 초기 유속은 현재 약 30단위의 이동 구간을 기준으로 하며, 하천 길이가 바뀌면 마감 시간도 함께 조정한다.

### 9.2. 5일 캠페인 초기값

| 일차 | 등장 재질 | 공급 간격 | 하류 유속 | 오늘의 목표 |
|---:|---|---:|---:|---:|
| 1일 | 플라스틱, 금속 | 2.0초 | 초당 1.20 | 30점 |
| 2일 | 플라스틱, 금속, 유리 | 1.8초 | 초당 1.35 | 50점 |
| 3일 | 네 재질 모두 | 1.6초 | 초당 1.50 | 70점 |
| 4일 | 네 재질 모두 | 1.4초 | 초당 1.65 | 90점 |
| 5일 | 네 재질 모두 | 1.2초 | 초당 1.80 | 110점 |

- 공급 확률은 분리수거 쓰레기 88%, 목재 12%다. 쓰레기 확률은 그날 활성 재질에 균등 분배한다.
- 같은 재질의 외형은 균등 추첨한다. 첫날 목재는 나뭇가지만, 2일차부터 나뭇가지:통나무를 3:1로 추첨한다.
- 현재의 카테고리 2:2:2:3:1과 희귀도 4:2:1 가중치는 새 버전에서 사용하지 않는다.
- 전날의 기물은 정산 때 정리하고, 다음 날은 비어 있는 작업 구역에서 시작한다.
- 재시도 시 같은 날의 공급 순서와 위치 시드를 재사용하여 같은 조건에서 다시 도전하게 한다.

### 9.3. 난이도 수치의 산술 예시

첫날 쓰레기 26개가 공급됐다고 가정하면, 14개를 4·4·4·2개 묶음으로 올바르게 제출하고 12개를 놓친 결과는 `18 + 18 + 18 + 7 - 24 = 37점`이다. 목표 30점을 통과한다.

마지막 날 쓰레기 44개 중 32개를 4개 묶음 8회로 제출하고 12개를 놓친 결과는 `18 × 8 - 24 = 120점`이다. 목표 110점을 통과한다. 일차가 오를수록 올바르게 처리해야 하는 비율과 묶음 운반의 활용도가 높아지는 초기 구성을 의도한다. 이 예시는 플레이 측정값이 아니라 목표 설정을 위한 계산이다.

### 9.4. 실패와 재시도

- 목표 미달 시 ‘오늘 다시’와 ‘처음부터’를 제공한다.
- ‘오늘 다시’는 해당 일차 시작 시점의 목재와 업그레이드를 복원한다. 실패한 시도에서 회수한 목재는 이월하지 않는다.
- ‘처음부터’는 1일차, 초기 능력치, 목재 0으로 돌아간다.
- 마감 전 쓰레기를 놓쳐도 즉시 종료하지 않는다. 남은 시간에 다른 묶음으로 감점을 만회할 수 있다.

## 10. 퇴근 후 업그레이드

성공한 날 사이에 목재를 사용한다. 시간 제한 없이 구매하거나 건너뛸 수 있으며, 목재는 한 플레이 내에서만 유지한다. 5일차 후에는 구매 화면 대신 최종 결과를 표시한다.

| 업그레이드 | 초기 → 1단계 → 2단계 → 3단계 | 단계별 비용 |
|---|---|---|
| 튼튼한 앞발 | 운반 한도 6 → 8 → 10 → 12개 | 2 / 4 / 7목재 |
| 든든한 식사 | 기본 이동 속도 4.5 → 5.0 → 5.5 → 6.0 | 2 / 4 / 7목재 |
| 긴 집게 | 집기 거리 1.8 → 2.1 → 2.4 → 2.7 | 2 / 4 / 7목재 |

- 한 번의 퇴근 화면에서 여러 항목을 살 수 있다. 구매할 때만 목재를 차감한다.
- 업그레이드 후 현재값과 다음 단계의 값을 짧게 함께 표시한다.
- 업그레이드는 처리 효율을 높인다. 분류가 틀렸을 때의 감점이나 폭포로 빠지는 쓰레기의 비용을 없애지 않는다.
- 큰 묶음을 만들기 쉬운 운반 한도와 왕복 시간을 줄이는 이동 속도가 서로 다른 선택이 되게 한다.

## 11. UI와 피드백

### 11.1. 항시 정보

- 상단: `N일차`, 공급/마감 상태와 남은 시간, `오늘 점수 / 목표`, 목재 보유량.
- 운반 중: 운반 개수/한도와 재질별 아이콘 수량. 긴 능력 설명은 기본 화면에 펼치지 않는다.
- 투입구: 재질 아이콘과 짧은 이름. 접근하면 제출 예상 점수와 E 안내를 표시한다.
- 화면 밖의 폭포 정산: 해당 방향에 획득 목재 또는 감점 표시. 가까운 시점의 정산은 모아 보여준다.

### 11.2. 접착과 분류 정보

- 집을 수 있는 대상은 기존 호버 외곽선으로 강조하고, 범위 밖이면 제한을 알 수 있게 표시한다.
- 운반 묶음과 같은 쓰레기 재질은 접착 후보로 강조한다. 다른 재질을 붙이려는 순간에는 혼합 경고를 보여준다.
- 혼합 묶음은 운반 UI에서 섞인 재질 아이콘을 함께 보여준다. 잘못 붙인 이유를 숨기지 않는다.
- 투입구 예고는 실제 제출과 같은 규칙으로 계산한다. 정상 점수·묶음 보너스·오분류 감점을 짧게 구분한다.
- 제출은 기물이 투입구로 끌려들어가는 연출, 점수 숫자와 소리로 표시한다. 감점은 별도 색상과 하향 표시로 구별한다.
- 목재 회수는 점수와 다른 아이콘을 사용하고 `+N 목재`로 표시한다.

### 11.3. 하루 결과

정상 제출 개수, 오분류 개수, 놓친 쓰레기 개수, 가장 큰 정상 묶음, 오늘 순점수와 목표, 획득한 목재를 표시한다. 성공 여부와 다음 행동 버튼을 먼저 읽을 수 있도록 배치한다.

### 11.4. 화면 구성과 씬 편집

- 화면 고정 UI에는 일차·시간·점수·목재·운반 현황·조작 안내·결과와 업그레이드만 둔다. 설명은 짧은 한글 문구로 표시한다.
- 투입구 이름과 제출 안내는 투입구 위 World Space 표지로 표시한다. 게임 HUD와 결과 패널은 Screen Space UI로 구성한다.
- 비버·투입구·HUD는 `Assets/Scenes/Game.unity`의 씬 오브젝트로 편집한다. 공급 자재는 `Assets/Resources/Prefabs/Recycling/`, 등장 규칙은 `Assets/Resources/Data/RecyclingCatalog.asset`에서 수정한다.

- `RecyclingGrassTools`: `Tools > Beaver > Rebuild Terrain Grass` 메뉴에서 환경 지형 표면에 맞춘 잔디 메시를 재생성한다.

## 13. 구현 상태와 확인 기준

1. 완료: 비버 이동, 거리 제한 집기, 재집기, 연결 묶음 운반과 Q 분리를 구현했다.
2. 완료: 분류별 자재 데이터와 날짜별 공급 풀, 4개 투입구, 제출 점수 예고 및 정산을 구현했다.
3. 완료: 폭포에서 쓰레기 감점과 접촉 여부와 무관한 목재 보상을 기물별로 한 번 처리한다. 투입구의 목재는 보상·감점에서 제외한다.
4. 완료: 공급·마감·하루 정산과 운반 중 자재 처리, 일일 목표 판정을 연결했다.
5. 완료: 업그레이드 구매, 실패 시 하루 시작 상태 복구, 재시도를 연결했다.
6. 완료: 5일 캠페인, 최종 클리어, 일시정지, 조작 안내, 분류 피드백 UI를 구성했다. 전용 씬 진입으로 이전 배치형 게임 규칙은 새 정산에 들어오지 않는다.
7. 완료: 공급 종료 뒤 강 위의 기물이 모두 사라지면 하루를 즉시 정산한다.
8. 완료: 마우스 드래그 카메라 이동과 비버 중심 복귀 UI를 제거하고, 짧은 우클릭 추적과 휠 줌을 유지한다.
9. 완료: 비버가 방향을 바꾸면 운반 중인 묶음도 비버 루트를 중심으로 함께 회전한다.

## 14. 구현 구조와 Unity 확인 항목

핵심 시스템은 `Assets/Scripts/BeaverRecycling/`에 있고, 카탈로그와 자재 프리팹은 `Assets/Resources/` 아래에 둔다. 비버·투입구·HUD는 Game 씬에서 수정할 수 있도록 씬 오브젝트로 구성했다.

- 하루 목표와 오분류/방치 감점: 실수 한두 번을 만회할 수 있는지, 후반의 요구 처리율이 적절한지 확인한다.
- 공급 간격·유속·작업 구역 길이·마감 시간: 마지막 공급 기물에도 처리 기회가 있는지 함께 조정한다.
- 이동 속도·집기 거리·투입구 간 거리: 분류 판단보다 왕복 이동만 오래 걸리지 않는지 확인한다.
- 운반 한도·이동 감속·묶음 배율: 매번 최대 크기까지 기다리는 전략만 유리해지지 않는지 확인한다.
- 목재 비율·목재량·업그레이드 비용: 점수를 포기할 만큼 목재만 유리하거나, 목재 회수의 효과가 너무 늦게 나타나지 않는지 확인한다.
- 조인트와 기물 충돌 설정: 큰 묶음이 떨리거나 비버 이동을 끌어당겨 조작을 방해하지 않는지 확인한다.

- 잔디 메시 재생성 메뉴: Tools > Beaver > Rebuild Terrain Grass. 환경 프리팹의 위쪽 지형 삼각형에 잔디 뿌리를 맞춘다.
- Unity에서 에셋 임포트 후 Game 씬을 열어 입력, 기물 결합/분리, 제출 정산, 폭포 정산, 하루 결과와 재시도를 Play Mode로 확인한다.
- 다음 조정 수치는 목표와 오분류/방치 감점, 공급 간격·유속·마감 시간, 운반 한도, 목재량과 업그레이드 비용, 충돌 안정성이다.
